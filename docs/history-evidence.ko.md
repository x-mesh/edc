# 관측 시각 주변의 저장 증거

터미널에서 `edc history`를 열고 저장된 top 실행을 고른 뒤, `t`로 그 관측값을 열어 표본을 고르고 `e`를 누릅니다. 그러면 그 실행과, 선택한 표본의 앞뒤 5분 구간으로 기존 overview가 열립니다. 이 범위는 그 실행에 기록된 표본 범위 안으로 좁힙니다. Esc를 누르면 선택한 관측값으로 돌아갑니다.

범위를 직접 정하거나 대화형이 아닌 출력을 쓰려면 다음과 같이 실행합니다.

```sh
edc history overview --run RUN_ID --from 2026-11-23T01:25:00Z --to 2026-11-23T01:35:00Z
edc history overview --run RUN_ID --from 2026-11-23T01:25:00Z --to 2026-11-23T01:35:00Z --json -
```

저장 증거 절은 다음을 합쳐서 보여 줍니다.

- 저장된 `events.window` snapshot 결과의 구조화된 event 시각.
- 저장된 `changes.*` 결과에서 시각이 있는 package, 설정, 서비스 변경.
- 범위 안에서 시작했거나, 알려진 실행 시간이 범위와 겹치는 명령 로그의 메타데이터.

항목은 실제 event 시각 순으로 정렬합니다. snapshot을 저장한 시각은 JSON의 `captured_at`에 따로 남기므로, 나중에 찍은 snapshot이 더 이른 event를 담을 수 있습니다. 선택한 실행에는 저장된 hostname이 정확히 같은 snapshot 증거만 붙습니다. 여러 호스트의 overview에서는 snapshot 항목마다 기록된 hostname을 표시합니다.

명령 로그 기록에는 호스트 정보가 없습니다. 그래서 그런 항목은 `host_unknown: true`를 가지며, 선택한 실행의 호스트에서 나온 증거가 아니라 범위를 정할 수 없는 보관 증거로 표시합니다. 실행 시간만 겹치는 명령은 원래의 시작·종료 시각을 그대로 두고 `overlap: true`를 가집니다. 종료 시각을 모르면 겹친다고 가정하지 않습니다. 기존 명령 로그 목록(`l`, Enter)은 시작 시각으로 맞추는 방식을 그대로 씁니다. 겹치기만 하는 항목은 JSON의 `log_key`/`log_path`와 명령 로그 보관소에서 볼 수 있습니다.

이 기록들은 시간이 겹칠 뿐, 원인 관계를 밝히지 않습니다. 이력을 읽는 쪽은 명령을 실행하거나 지금 호스트에서 event와 변경을 다시 수집하지 않습니다.

새 Linux와 macOS event snapshot은 시간대가 붙은 구조화된 event 시각을 저장합니다. 이전 event snapshot에는 시간대 없이 현지 형식으로 적힌 Evidence 글만 있습니다. 이런 snapshot은 지금 시간대로 해석하지 않고, 시각을 맞출 수 없다고 보고합니다. 기존 Evidence는 snapshot 내보내기와 report 보기에서 그대로 볼 수 있습니다.

읽는 쪽은 저장된 SKIP 결과, 잘못된 데이터, 없는 snapshot 표, 예전 형식의 시각, 원천 경고, 잘림을 보고합니다. 절이 비어 있으면 쓸 수 있는 저장 증거를 찾지 못했다는 뜻이고, 사고가 없었다는 뜻은 아닙니다.

읽기 한도는 저장 결과 후보 1,000개, 결과마다 8 MiB, 저장 데이터 전체 32 MiB, 시간순 항목 200개입니다. 항목 수 한도에 닿으면 범위를 정할 수 없는 명령 로그보다 snapshot 증거를 먼저 남기며, 마지막 표시는 시간순입니다. 반복되는 snapshot 증거는 하나로 합칩니다. 적용된 한도는 증거 안내에 밝힙니다. 기존의 저장된 event 시간순 목록은 따로 50개에서 자르고, 그 사실도 밝힙니다.
