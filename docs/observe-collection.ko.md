# 관측 명령의 수집 범위

`proc`, `svc`, `jobs`, `changes`는 관측 대상의 상태와, 그 데이터를 수집할 수 있었는지를 구분합니다. 서비스나 예약 작업은 그 상태를 문제없이 관측했어도 실패한 상태일 수 있습니다. 일부만 읽은 snapshot이 정상으로 보여도, 읽지 못한 원천이 정상이라는 뜻은 아닙니다.

글 출력은 기존 pass/warn/fail/skip 판정을 그대로 두고, 수집 요약을 따로 더합니다.

```text
Collection: 3 observed · 1 partial · 1 permission denied
3 pass  ·  1 warn  ·  0 fail  ·  1 skip
```

수집 요약의 수는 표시가 붙은 원천·결과의 수이고, 작업, process, 파일, socket의 수가 아닙니다. 원천별로 일부만 읽었거나 읽지 못한 내용은 해당 결과 옆에 나옵니다. 자세한 출력에서는 성공한 수집 내용도 보여 줍니다. 서비스 브라우저는 수집 범위를 표 위의 별도 줄에 둡니다.

| 수집 상태 | 뜻 |
| --- | --- |
| `observed` | 수집기가 문서에 적힌 원천 범위를 문제없이 관측했습니다. 호스트 전체를 다 읽었다거나, 선택 지표가 모두 있다는 뜻은 아닙니다. |
| `partial` | 알려진 누락이나 수집 한도 때문에 읽지 못한 데이터가 있습니다. 관측 수는 최소값입니다. |
| `permission_denied` | 권한 오류 때문에 원천을 읽지 못했습니다. 항목 수를 꾸며 내지 않습니다. |
| `unsupported` | 이 플랫폼에서 지원하지 않거나 쓸 수 없는 원천·backend입니다. |
| `unavailable` | 원천을 읽을 수 없거나 설정되지 않았거나, 알려진 대상을 관측하지 못했습니다. 0을 꾸며 내지 않습니다. |

비어 있는 목록을 문제없이 읽으면 `observed: 0`입니다. 읽지 못한 원천은 관측 수를 빼고 보여 줍니다. 관측 수가 0인 `partial`은 읽을 수 있는 부분에서 아무것도 관측하지 못했다는 뜻이고, 맞는 항목이 없다는 뜻은 아닙니다.

수는 원천마다 다릅니다. 예를 들어 `proc.fd`는 descriptor를, `svc.fd`는 process FD 읽기를 셉니다. 서비스 목록은 TUI 표시용 필터를 적용하기 전에 돌려받은 서비스를, jobs는 예약 작업 기록을, changes는 요청한 시간 범위에서 관측한 event를 셉니다. 서로 다른 원천의 수를 더해 호스트 합계로 쓰면 안 됩니다.

기존 원천 범위의 한계는 그대로 적용됩니다.

- 서비스 FD 점검은 선택한 process 읽기로 범위가 정해집니다. 알려진 main PID가 process 표본에 없으면, 관측했는데 비어 있는 서비스로 보지 않습니다.
- socket 소유자와 journal은 계정 권한에 따라 제한될 수 있습니다. 일부 기록만 보이는 숨겨진 journal은 partial입니다.
- 서비스 목록 필터는 수집기가 요청할 서비스를 고릅니다. TUI의 글 필터나 실패만 보기 필터는 표시만 좁히고 원천 범위는 바꾸지 않습니다.
- cron은 마지막 실행 결과를 남기지 않습니다. 이 정보 한계만으로는 실패나 partial 목록으로 분류하지 않습니다.
- launchd 수집은 질의한 domain과 설정된 로그 끝부분을 설명할 뿐, 모든 domain이나 로그 파일 전체를 뜻하지 않습니다.
- changes 보고는 원천 데이터를 일부 읽었을 때, 알려진 읽기 불가 항목, 지원하지 않아 건너뛴 회전 형식, 검색 한도에 따른 잘림을 partial로 표시합니다.

## JSON 호환성

기존 상태 판정, 지표, 오류, 경고, 종료 코드 규칙은 뜻이 그대로입니다. 영향을 받는 결과에는 선택 항목인 메타데이터가 더해집니다.

```json
{
  "collection": {
    "state": "partial",
    "observed": 2
  }
}
```

`reason`은 선택 항목이며, 보고서의 기존 가림 경로를 거칩니다. 이전 결과와 관련 없는 명령에는 `collection`이 없습니다. 번역된 요약, 임의의 경고 글, 상태 판정으로 다시 분류하지 않습니다. 그래서 저장된 이전 보고서를 보여 줄 때 수집 범위를 추측해 붙이지 않습니다.
