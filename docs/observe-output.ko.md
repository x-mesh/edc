# 한 번 출력하는 관측 결과

터미널에 쓸 때 `proc`, 한 번 출력하는 `svc`, `jobs`, `changes`는 표시하는 긴 칸을 쓸 수 있는 폭에 맞춰 줄바꿈합니다. 상태와 probe 이름은 그대로 보이고, 그 뒤에 요약, 오류, 경고, 근거 글이 잘리지 않고 나옵니다. 근거를 보여 주는 조건과 수집 한도는 바뀌지 않습니다. 자세한 수집을 켜거나 숨긴 근거를 드러내지 않습니다.

결과 상세는 줄바꿈하기 전에 기존의 일반 상세 형식을 그대로 쓰므로, 오류·근거 규칙과 수집 범위 표시가 같게 유지됩니다. 결과 상태 머리글은 색을 켰을 때 색을 유지합니다. 아래쪽 요약은 좁은 화면에서도 수와 상태가 붙어 있도록 색 없는 수/상태 쌍을 씁니다.

배치는 실제 출력 터미널의 폭을 씁니다. `NO_COLOR`는 색만 끄고, 폭에 맞춘 배치는 끄지 않습니다. 넓은 터미널에서는 데이터가 다 들어가면 기존의 촘촘한 행을 유지합니다. 좁은 화면의 서비스·변경 표는 행마다 줄바꿈한 항목 덩어리 하나를 써서, 표시하는 항목 이름 전체를 상태, 숫자, 시각, 상세와 떼어 놓습니다.

기존 서비스·container TUI 모델, 선택, 새로 읽기 동작, 고정 높이 행은 바뀌지 않습니다. `svc`는 대화형 컬러 터미널에서 기존 브라우저를 그대로 열 수 있고, 폭에 맞춘 한 번 출력 형식은 명령이 글 출력 경로를 탈 때만 적용됩니다.

pipe와 파일 출력은 기존 미리보기 한도를 포함해 기존 글 형식을 그대로 씁니다. JSON 구조와 상태에 따른 종료 코드도 바뀌지 않습니다. 도구에 넘기려고 원래의 한 줄 표현이 필요하면 pipe나 JSON을 사용합니다.

```sh
edc proc 1234 -v
NO_COLOR=1 edc jobs
edc changes --since 1h
edc svc web.service
edc proc 1234 --json -
edc changes | cat
```

가림은 줄바꿈보다 먼저 합니다. 그래서 IP 주소가 가려지기 전에 여러 줄로 나뉘는 일이 없습니다. 형식을 만들 때는 칸의 복사본을 쓰고, 원래 보고서가 쓰는 event·서비스 묶음은 형을 그대로 둡니다.

`next:` 명령은 줄바꿈을 넣지 않고 출력하므로, 경로가 든 따옴표 인자를 그대로 복사할 수 있습니다. 화면에서는 터미널이 그 줄을 접어 보일 수 있고, 설명 칸과 달리 출력 바이트가 화면 폭을 넘을 수 있습니다. 기존 원천의 미리보기 한도와 터미널 제어 문자 정리는 그대로 적용됩니다.
